# みかん結露チェッカー

果実温度と室温・相対湿度から結露リスクを判定する、日本語のスマートフォン向けPWAです。HTML / CSS / JavaScriptのみで動作し、外部ライブラリ・API・通信による計算は使用しません。

## 使い方

1. アプリを開き、果実の表面温度、接触する空気の室温、相対湿度を入力します。
2. 数値入力、または＋／−ボタンで値を変更します。温度ボタンは0.5℃、湿度ボタンは1％刻みです。
3. 自動的に判定されます。「判定する」を押すと結果まで移動します。
4. 露点、果実温度、差、リスク、低リスクの目安までの必要昇温量を確認します。

温度の範囲は−10〜50℃、湿度は1〜100％です。小数も入力できます。範囲外・空欄・数値でない入力ではエラーを表示し、判定を停止します。最後の有効な3項目をlocalStorageへ保存し、再度開くと復元します。保存できないブラウザでも計算は利用できます。

## ホーム画面への追加

初回は通信がある状態でHTTPSの配信先を開き、「オフラインでも利用可能」の表示を確認してください。

- iPhone：Safariで開き、共有メニューから「ホーム画面に追加」を選択します。
- Android：Chromeで開き、メニューの「ホーム画面に追加」または「アプリをインストール」を選択します。

メニュー名はOSやブラウザのバージョンで異なります。インストール後、機内モードでも起動・計算できます。初回キャッシュ前、ブラウザのサイトデータ削除後は再度オンラインで開く必要があります。ホーム画面と通常ブラウザの保存領域が分離される環境では、それぞれで入力値を保存します。

## ローカルで起動

`dist`を静的HTTPサーバーで配信します。Pythonがある場合、プロジェクトフォルダーで次のように起動できます。

```sh
python -m http.server 8000 --directory dist --bind 127.0.0.1
```

`http://127.0.0.1:8000/`を開きます。PWAはHTTPSまたはlocalhost / 127.0.0.1が必要です。ファイルを直接開く方法やスマホからLANのHTTPアドレスに接続する方法ではService Workerを利用できません。スマホではHTTPSの配信先を使用してください。

## 計算と判定

Magnus式：`γ = ln(RH/100) + 17.625×T/(243.04+T)`、`露点 = 243.04×γ/(17.625−γ)`。Tは室温℃、RHは相対湿度％です。

係数の参照：[FAA AEDT 4a Technical Manual、2.2.3.1.2](https://aedt.faa.gov/Documents/AEDT4a_TechManual.pdf)。水に対する露点の近似であり、氷に対する霜点ではありません。

| 果実温度−露点 | 判定 |
| --- | --- |
| 0℃以下 | 高 |
| 0℃より大きく2℃未満 | 注意 |
| 2℃以上 | 低 |

判定は丸める前の値を使い、表示は小数第1位です。2℃ちょうどは「低」を優先します。必要昇温量は`max(0, 露点+2−果実温度)`を0.1℃単位で切り上げます。目標温度も切り上げて表示するため、表示値を満たしたときに目安に不足しません。

初期値10℃ / 20℃ / 70％では露点14.4℃、差−4.4℃、「高」、必要昇温量6.4℃です。これは空気条件が変わらない場合の目安で、所要時間や腐敗リスクを予測するものではありません。

## ファイル構成と拡張

- `dist/index.html`：画面、アクセシビリティ、PWA用メタ情報
- `dist/style.css`：スマホ優先のレスポンシブ表示
- `dist/app.js`：独立した計算層`MikanCalculator`、保存、入力と結果の制御
- `dist/manifest.json`：アプリ名、起動範囲、表示とアイコン設定
- `dist/service-worker.js`：初回にアプリ一式を保存し、通信不能時にページを提供
- `dist/icons/`：192px / 512pxアイコン、マスク対応512px、Apple用180px
- `verify.cjs`：Node.jsで実行する計算確認
- `.openai/hosting.json`：Sites配信設定

将来の冷蔵庫から出す時刻、輸送温度、外気温などは入力項目として追加し、計算層に評価関数を追加できます。腐敗リスクは別の評価モデルが必要です。画面・保存処理・計算式を分離しているため、個別に拡張できます。

変更を配信するときはService Workerの`CACHE`を新しいバージョンへ変更してください。更新後は新しいファイル群をまとめてキャッシュします。保存済み入力値のスキーマ変更時はstorageKeyの変更または移行処理も検討してください。

- Node.jsの構文チェック、初期値、露点一致、差2℃の境界、異常入力、温湿度1300条件の計算：合格
- ブラウザで自動計算、ボタン、上限時のボタン無効化、空欄エラー、保存と再読み込み復元：確認済み
- 幅390px / 320pxのレスポンシブ表示：確認済み。320pxで横スクロールなし、ボタン高さ58px以上
- ローカルHTTPサーバーを停止して再読み込みし、キャッシュからの起動と＋ボタンでの再計算：確認済み
- 実機のiPhone / Androidでのインストール操作は未検証です。

計算確認はプロジェクトフォルダーで`node verify.cjs`を実行します。
